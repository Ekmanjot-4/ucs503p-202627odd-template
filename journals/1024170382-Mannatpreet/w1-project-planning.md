# Project Planning and Requirements Analysis

## Objective

The main objective of the first week was to discuss our project idea, Algo Recall — DSA Revision Tracker & Analyzer, with the team and decide what we actually wanted to build. Before starting the coding part, we wanted to have a clear idea about the purpose of the project, its scope, the users who would use it, and the features we wanted to include.

## Relevant Context

During the first week, most of our work was related to project planning and discussions with the team. We discussed the problem we wanted to solve and how our application could help students who practice Data Structures and Algorithms (DSA) questions.

The main things we discussed were:

- **Project Objectives:** Understanding the main purpose of Algo Recall and the problem it would solve for students who regularly practice DSA.
- **Functional Requirements:** Discussing the features that should be available in the application, such as adding questions, revising them, and tracking revision progress.
- **Project Scope:** Deciding which features we wanted to include in the initial version and which features were not necessary at this stage.
- **Potential Users:** Identifying the main users of the application, especially students and other learners who solve DSA questions and want to revise them later.
- **Use Cases:** Discussing how users would interact with the application, such as adding questions, viewing them on the dashboard, revising previously solved questions, and checking their progress.

## Key Observations

During our discussions, we realized that solving a DSA question once is not always enough, as it can be difficult to remember the approach after some time. Students often solve many questions but may not have a proper system to keep track of which questions they need to revise.

Keeping this problem in mind, we decided that Algo Recall would mainly focus on helping users manage their solved questions and revise them in a more organized way. We wanted the application to help users track their confidence in different questions and identify topics where they needed more practice.

We also understood that deciding the project scope and main requirements before starting development would make the further work easier. It would help us stay focused on the important features instead of adding too many things to the initial version.

## Preliminary Interface Design

Along with the project planning, I also prepared a handwritten first draft (which I should have ideally done on figma) of the application's overall interface. It included a rough idea of how the dashboard and other pages would look, along with the navigation bar and the different routes between pages.

I also noted down some basic user flows, describing what should happen when a user clicks on a particular button or navigation item. For example, I considered which page should open when the user selects an option from the navigation bar and how the user would move between different sections of the application.

This was only an initial and informal design, not a finalized UI design. However, it helped me get a clearer idea of how the application should be organized and how users would interact with its different pages.

## Outcome

By the end of the first week, we had discussed the main idea of Algo Recall, its functional requirements, project scope, potential users, and major use cases. I had also prepared a rough handwritten design of the dashboard, pages, and navigation flow.

Since this week was mainly focused on planning and understanding the project, no major coding work was done by me during this period. The discussions and initial design gave us a clearer direction for starting the frontend development in the following week.
